# 设备安全接入参考（身份 / 加密 / 密钥 / 平台侧 / 漏洞）

> 供 device-access-engineer 与主理人引用。所有方案必须落到「鉴权方式 + 加密通道 + 密钥管理 + 平台侧权限」四件事，缺一不可。

## 一、设备身份与鉴权模式

| 模式 | 说明 | 适用场景 | 主要风险 |
|------|------|----------|----------|
| 一机一密 | 每台设备独立密钥/证书，出厂烧录或首次激活下发 | 规模化商用（推荐默认方案） | 烧录与库存管理成本 |
| 一型一密（预注册） | 同型号共享产品密钥，首次激活换发唯一身份 | 大批量低价值设备 | 产品密钥泄露即全线风险，必须配合预注册白名单 |
| X.509 双向证书 | 设备与平台互验证书（mTLS） | 网关、高安全场景、工业 | 证书签发与轮换运维复杂 |
| 免密 / IP 白名单 | 无鉴权，仅限内网或 PoC | 严禁用于生产 | 任意伪造接入 |

## 二、传输加密

- MQTT over TLS：8883 端口（生产禁用明文 1883）
- CoAP over DTLS：5684；资源受限设备可用 PSK 模式降低开销
- HTTP/HTTPS：仅 HTTPS，禁用自签证书跳过校验
- **必须开启证书校验**：客户端不校验证书 = 可被中间人劫持，比明文更危险（看起来安全）
- NB-IoT/LoRa 场景若链路本身加密，仍建议应用层加签防重放

## 三、密钥与证书生命周期

1. **签发**：平台侧 CA 签发，私钥在安全环境生成
2. **下发**：首次激活通过安全通道（或产线烧录），禁止明文下发
3. **存储**：私钥不得硬编码在可读固件分区；优先安全芯片（SE）/TEE
4. **轮换**：定期轮换（如 1 年）或泄露后立即轮换，需支持不停机换证
5. **吊销**：设备报废/丢失即吊销，平台侧维护吊销列表

## 四、平台侧安全

- **Topic 级权限**：设备只能发布/订阅自己的 `sys/{productKey}/{deviceName}/...` 主题，禁止通配符越权
- **越权检测**：同一设备多地登录、异常高频连接、非注册设备上报 → 告警并拉黑
- **指令鉴权**：命令下发需签名/令牌，防止伪造控制指令（尤其涉及阀门、开关、升降）
- **审计日志**：设备接入、配置变更、指令下发全留痕

## 五、常见漏洞清单（方案中应主动排查）

- 出厂默认密码未强制修改
- 全型号共享同一密钥
- 明文 MQTT / 跳过证书校验
- 调试串口/后门接口未关闭
- 固件未签名，可被刷入篡改包
- Topic 通配符过宽（`#`）导致可监听他人数据
- 旧固件长期在线，不强制升级

## 六、合规要点（国内场景）

- 数据传输加密、日志留存不少于 6 个月（等保要求）
- 涉及人脸/视频等个人信息需脱敏与本地化处理，遵循《个人信息保护法》
- 工业场景需评估是否涉及关键信息基础设施，安全方案需按等保级别设计

## 七、回答规范

- 必须同时给出「鉴权 + 加密 + 密钥管理 + 平台权限」四项，不能只说"用 TLS"
- 一机一密为默认推荐；若用户成本敏感选择一型一密，必须提示产品密钥泄露风险与预注册白名单要求
- 提及固件安全时必须包含**签名校验 + 防降级**两条
