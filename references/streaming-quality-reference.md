# 流式数据质检参考（在线 / 秒级 / 窗口 / 水位线）

> 供 data-quality-analyst 与主理人引用。批处理质检回答"过去哪里坏了"，流式质检回答"现在正在坏"。秒级/实时场景必须用后者。

## 一、适用与边界

- **适用**：产线秒级采集、电力实时量测、车辆/工程机械、秒级告警联动场景
- **不适用**：计费/结算类对账（仍需离线批处理复核）
- **结论**：在线发现问题 + 离线复核口径，两者并存；**两侧口径必须一致**，否则会互相打脸

## 二、滑动窗口指标（在线计算）

| 指标 | 窗口 | 计算方式 |
|------|------|----------|
| 上报率 | 1–5 分钟滚动 | 窗口内实际条数 ÷ 应有条数 |
| 延迟分布 | 5 分钟 | P50/P95/P99 端到端延迟 |
| 异常率 | 5–15 分钟 | 窗口内异常点数 ÷ 总点数 |
| 卡值计数 | 连续窗口 | 窗口内相同值连续次数 ≥ 阈值 |
| 丢包突发 | 1 分钟 | 设备实时断流检测（应为 N 条，实收 0） |

## 三、在线异常检测算法（按算力选择）

1. **EWMA（指数加权移动平均）**：内存占用低，适合百万级测点；偏离 EWMA ± k×σ 判异常
2. **滑动 z-score**：窗口内均值/标准差滚动更新，实现简单
3. **同比环比**：与昨日/上周同时段比较（需存历史基线），适合日周期明显的负荷类指标
4. **状态机**：正常 → 疑似（连续 N 次异常）→ 确认告警 → 恢复，避免瞬时抖动直接告警
5. **固定量程**：超出物模型 min/max 直接判异常（最便宜、最有效的一条）

## 四、事件时间与乱序处理（流式质检的关键坑）

- 必须按**事件时间**（设备采集时间）而非处理时间计算窗口，否则延迟数据会算错窗口
- 设置**水位线（watermark）**：容忍乱序 30 秒（可配置），超时数据进迟到侧输出
- **迟到数据**：到达后回补并修正对应窗口指标，同时标记"指标已修正"
- **时钟漂移**：设备时间不可信时以平台接收时间为准，并单独监控漂移量
- 无设备时间戳的协议（如部分 Modbus 场景）需网关打时间戳，方案中必须写明谁打时间戳

## 五、在线质检结果的去向

- 直接触发告警（与告警规则联动，避免"质检发现 → 人工查看 → 再告警"的二次延迟）
- 写入质量指标时序库，供大屏与日报使用
- 异常样本落盘（含原始报文），供离线复核与模型迭代

## 六、资源与实现建议

- 10 万点/秒以内：MQTT Broker 规则引擎 + 时序库即可
- 10 万–100 万点/秒：Flink / Kafka Streams + 分区并行，按设备 ID 哈希分区保证同一设备进同一实例
- 窗口状态需持久化（检查点），否则重启丢窗口
- 采样降级：超高频率指标可先降采样再质检，避免算力打爆

## 七、回答规范

- 秒级场景必须明确：窗口大小、异常判定算法、乱序容忍、迟到处理、是否联动告警
- 必须说明在线与离线口径如何保持一致（同一指标定义、同一时间栅格）
- 不得把批处理方案（按天/小时统计）直接套到秒级场景，这是最常见的答非所问
