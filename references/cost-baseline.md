# IoT 上云成本基线（量级参考）

> 供主理人在「方案咨询/成本估算」中引用。**所有数字为公开定价量级的区间参考（2020s 中后期市场水平），不是报价**；实际以云厂商当期价目表与项目议价为准。回答中引用时必须注明"量级参考，非正式报价"。

## 一、公有云 IoT 平台计费项（主流厂商计费模型大体一致）

| 计费项 | 计费方式 | 量级参考 |
|--------|----------|----------|
| 设备连接 | 按同时在线设备数/月 | 约 ¥1–5 / 设备 / 月（含基础消息额度） |
| 消息数 | 按条计费（上行+下行分别计） | 约 ¥1–5 / 百万条（超额度部分） |
| 存储 | 时序数据按 GB·月 | 约 ¥0.1–1 / GB / 月（热存）；冷存更低 |
| 规则引擎/流转 | 按规则条数或处理消息数 | 约 ¥0.5–3 / 万条处理 |
| 公网流量 | 按 GB 出方向 | 约 ¥0.5–1 / GB |
| 函数计算（消息处理） | 按调用次数+资源时长 | 约 ¥1–2 / 百万次 + 资源费 |

**快速估算公式**（30 台、5 分钟上报、单条 200B 的小型项目）：
- 月消息量 = 30 × 12 × 24 × 30 ≈ 25.9 万条 ≈ 0.26 百万条
- 月数据量 = 25.9 万 × 200B ≈ 52 MB
- 结论：此类小项目平台侧月费通常在 **几百元以内**（连接费为主），存储可忽略

**规模化参考**：1,000 台 × 1 分钟上报 → 月消息约 4,320 万条；10,000 台 → 约 4.3 亿条，此时消息费与连接费成为主要成本，需按量级单独核算并考虑包年/预留折扣。

## 二、网络与硬件侧成本（一次性 + 持续）

| 项目 | 量级参考 | 说明 |
|------|----------|------|
| NB-IoT/LoRa 通信模组 | ¥15–60 / 台 | 模组型号与认证影响大 |
| 4G Cat.1 模组 | ¥30–80 / 台 | 需公网直连时常用 |
| 物联网卡流量 | ¥3–20 / 台 / 年 | 按流量档位，NB 场景更低 |
| 边缘网关（工业协议转换） | ¥800–5,000 / 台 | 按协议路数、算力、防护等级 |
| LoRa 网关 | ¥2,000–8,000 / 台 | 按覆盖半径与并发 |
| 传感器（温湿度类） | ¥50–300 / 只 | 精度与防护等级决定价格 |
| 现场施工/调试 | ¥100–500 / 点位 | 含布线、安装、联调 |

## 三、自建平台成本（对比参考）

| 项目 | 量级参考 |
|------|----------|
| 云服务器（接入+应用，2–4 核 8G） | ¥300–1,500 / 月 |
| MQTT Broker 集群（EMQX 等，按连接数） | 开源版免费；企业版按连接数计费，千级连接约数千元/年起 |
| 时序数据库（TDengine/InfluxDB 托管） | ¥500–3,000 / 月（按数据量） |
| 人力（1 名后端 + 0.5 名运维） | ¥30–60 万 / 年（隐性成本，常被低估） |

**决策速判**：设备数 < 5,000 且无强定制需求 → 优先公有云 IoT 平台（省人力）；设备数 > 5 万或有数据不出域/私有协议深度定制 → 评估自建或混合架构。

## 四、成本优化建议（方案中应主动提出）

1. **批量上报**：多测点合并单包发送，消息条数直接降 5–10 倍
2. **变化上报 + 心跳兜底**：静止数据不重复上报，仅定时心跳保活
3. **冷热分层**：原始数据 30 天热存，之后转冷存或降采样归档
4. **连接复用**：网关汇聚多设备共享一条连接，减少连接数费用
5. **包年/预留**：规模确定后签包年，通常比按量便宜 30%–50%

- 必须先给**假设**（设备数、上报频率、单条大小、在线率），再给成本区间
- 必须区分**一次性投入**（模组/网关/施工）与**持续费用**（平台/流量/存储）
- 必须注明"量级参考，非正式报价，需按云厂商当期价目表核算"
- 不得编造精确到元的报价；不确定时给区间
