# 告警规则设计参考（分级 / 去抖 / 静默 / 收敛 / 指标）

> 供主理人与成员引用。告警能力的分水岭不是"能不能报"，而是"报得准、不刷屏、有人管"。

## 一、告警分级（默认四层）

| 级别 | 触发示例 | 通知方式 | 响应时限 |
|------|----------|----------|----------|
| P0 紧急 | 设备离线超阈值且为关键设备、安全入侵、停机/超温超压 | 电话 + 短信 + IM | 15 分钟内 |
| P1 重要 | 指标持续超阈值、连续丢包、充电/供电异常 | 短信 + IM + 派单 | 1 小时内 |
| P2 提示 | 短时波动、单点数据异常、电量偏低 | IM / 站内 | 当班处理 |
| P3 信息 | 上线/离线、配置变更 | 站内记录 | 无需响应 |

## 二、去抖与抑制（防误报的核心）

- **次数去抖**：连续 N 次采样越限（如 3 次）才触发，避免单点毛刺
- **时间去抖**：持续 T 秒/分钟越限才触发（如超温持续 2 分钟）
- **回差（滞回）**：触发阈值 ≠ 恢复阈值（如 >60℃ 触发，<55℃ 恢复），避免在阈值附近反复抖动
- **父子抑制**：网关离线时抑制其下所有设备的"离线"告警，只报网关根因
- **维护窗口**：设备检修期设置静默，避免无效告警

## 三、静默期与升级

- 告警确认后进入静默期（如 30 分钟），期内同测点不重复通知
- 未确认 N 分钟自动升级到上级/值班主管（升级链需在方案中写清）
- 重复触发次数达到 K 次可提升告警级别（如 P1 → P0）

## 四、阈值设计方法

| 方法 | 说明 | 适用 |
|------|------|------|
| 固定阈值 | 按工艺/设备手册给定上下限 | 有明确国标/工艺要求的场景 |
| 统计基线 | 同设备历史 P95/P99 或均值 ±3σ | 无明确阈值、波动规律稳定的指标 |
| 同期对比 | 与昨日/上周同时段对比，偏离 X% 告警 | 有明显日周期/周周期的负荷类指标 |
| 同类横向 | 与同型号设备中位数比较（IQR 1.5 倍外） | 大批量同质设备，找"沉默的异常" |
| 变化率阈值 | 单位时间变化量越限（如温度 5 分钟升 10℃） | 突变型故障，比绝对值更灵敏 |

## 五、收敛与聚合（防告警风暴）

- 相似告警按「设备 + 类型」在时间窗内合并为一条（附发生次数）
- 按站点/区域聚合展示，优先呈现根因（离线风暴中先看网关）
- 抑制规则：已知上游故障期间自动抑制下游派生告警
- 风暴保护：单位时间告警数超阈值时切换为摘要通知

## 六、告警质量指标（应纳入方案验收）

- 告警准确率 = 有效告警 ÷ 总告警（<70% 说明阈值或去抖设计有问题）
- 误报率、漏报率（需结合事后复盘）
- MTTA（平均响应时间）、MTTR（平均修复时间）
- 告警风暴次数、单设备日均告警数（>10 条/天通常意味着设计问题）

## 七、常见设计错误

- 阈值拍脑袋，无依据、无回差 → 抖动刷屏
- 只用固定阈值，忽略日周期 → 白天正常、夜间误报
- 无抑制规则，网关断网时上百条设备离线告警
- 告警无处置建议（"温度过高"却不告诉人该干什么）
- 告警只进平台不外发 → 无人真正响应

## 八、回答规范

- 设计告警必须同时给出：分级 + 触发条件（含去抖参数）+ 通知渠道 + 抑制规则 + 恢复条件
- 每条告警应附带「建议处置动作」，否则视为不可行动的告警
- 涉及安全类告警（入侵/越权/固件篡改）默认 P0
